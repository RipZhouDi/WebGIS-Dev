## 一、问题分析

### 核心症状

首次访问（localStorage 无任何语言偏好）时，英语用户的 Landing 落地页 / 登录页默认渲染**中文**，而非浏览器的默认语言。

### 根本原因

初始语言在语言 SSOT（`useLocale.js`）与偏好 store（`useUserPreferencesStore.ts`）各有一处硬编码默认值 `'zh-CN'`：

1. `useLocale.js` `readInitialLanguage()`：`localStorage.getItem('webgis_pref_language')` 为 `null` 时，`normalizeLocaleLanguage(null)` 恒返回 `'zh-CN'`（无分支不成立时默认收敛到中文）；catch 分支同样写死 `'zh-CN'`。
2. `useUserPreferencesStore.ts` `DEFAULT_PREFERENCES.language = 'zh-CN'`：`main.js` 启动时 `bootstrap()` → `loadFromStorage()` → `applyRuntimePreferences()` → `setLocaleLanguage(preferences.language || 'zh-CN')`，即使 `useLocale` 已按浏览器检测出 `en-US`，也会被这条链**立即覆盖回中文**。

因此仅改 `readInitialLanguage()` 一处不生效：旁观者视角 LandingView 的初始语言最终由 store 链决定。

### 受影响模块

- 语言初始化链路（`useLocale.js` / `useUserPreferencesStore.ts` bootstrap）
- 首屏页面：LandingView（本次关注点）、RegisterView、登录页等全部首屏
- 语言切换器初始高亮态（`language === option.value`）

### 候选方案对比

| 方案 | 说明 | 评价 |
|---|---|---|
| A. 只改 LandingView | `onMounted` 里无偏好时检测 `navigator.language` 并调 `setLanguagePreference` | ✗ 主引导链 `main.js bootstrap` 在组件挂载前已把检测结果覆盖为 zh-CN，且写入了 localStorage，组件层无法区分「系统检测写入」与「用户显式选择」；污染偏好 SSOT |
| B. 改全局初始语言检测 | `useLocale.js` 新增 `detectSystemLanguage()`（SSOT 内），`readInitialLanguage()` 无存储值时走检测；store 默认值与 `|| 'zh-CN'` 兜底同步改为检测结果 | ✓ 检测收敛在语言 SSOT 唯一入口，App 全页面一致，无偏好时顺带把检测结果持久化（后续访问直接命中），用户显式切换仍然优先 |

**选定方案 B。**

## 二、解决方案

### 实现步骤

1. `frontend/src/domains/common/app/useLocale.js`：
   - 新增导出 `detectSystemLanguage()`：读取 `navigator.language`（降级 `navigator.languages[0]`），规范化后以 `zh` 开头 → `'zh-CN'`，否则（含读取异常）→ `'en-US'`。
   - 改写 `readInitialLanguage()`：先读 `webgis_pref_language`，有非空值 → `normalizeLocaleLanguage`；无值或读取异常 → `detectSystemLanguage()`。
2. `frontend/src/domains/common/user/stores/useUserPreferencesStore.ts`：
   - import `detectSystemLanguage`；
   - `DEFAULT_PREFERENCES.language` 由硬编码 `'zh-CN'` 改为 `detectSystemLanguage()`（模块加载时求值一次）；
   - `applyRuntimePreferences()` 的 `|| 'zh-CN'` 兜底改为 `|| detectSystemLanguage()`。
3. LandingView.vue **零改动**：其语言由全局 `useLocale()` 读 `currentLanguage`，检测与回写均在 SSOT 内完成。

### 行为结果

| 场景 | 结果 |
|---|---|
| 已有本地偏好（用户显式切过 / 登录偏好回写） | 以偏好为准（优先级不变） |
| 全新访客，浏览器语言 `zh` 开头 | `zh-CN` |
| 全新访客，浏览器语言为其它（en、ja、de…）或无法读取 | `en-US` |

## 四、修改原因

符合用户对首屏语言归属的预期：中文用户看中文、英文（及其它语言）用户看英文；用户显式切换或登录偏好依然覆盖检测结果。避免 LandingView 单独处理导致的 SSOT 污染（见方案对比）。

## 五、影响范围

- 语言初始化链路（初始 `currentLanguage`、`document.documentElement.lang`）
- LandingView / RegisterView / 登录页首屏文案与语言切换器高亮
- 全新访客与已登录访客首次语言偏好回写的取值来源
