# 2026-08-16 V3.5.23 首屏语言默认值收尾：远端空语言不再归 zh-CN · 偏好表单占位跟随系统

- **日期与时间**：2026-08-16 11:05
- **任务等级**：L2（V3.5.22 遗留两项修复，跨 3 个代码文件 + 文档）
- **触发来源**：用户指示「修复」上一版本日志遗留与风险中列出的两项：
  1. 远端 `language` 为空仍归一 `zh-CN`（原判「极端组合暂不处理」）
  2. 偏好表单草稿 `language: 'zh-CN'` 占位（原判「不可达未改」）

---

## 一、问题分析

### 核心症状与根本原因

| 遗留项 | 现状 | 根因 | 可达路径 |
|---|---|---|---|
| ① 远端语言为空归 zh-CN | `normalizePreferences` 用 `normalizeLanguage`（即 `normalizeLocaleLanguage`）归一远端 payload：空值/缺失恒回 `zh-CN` | `normalizeLocaleLanguage` 契约「非 en-us 一律 zh-CN」，空串也不例外；偏好映射层没有区分「未设置偏好」与「显式中文」 | 登录后 `loadPreferences` / `savePreferences` 合并远端响应；面板打开时 `FloatingAccountPanel` 本地 normalize 同样折叠（远端 `saved` 空语言 → 草稿显示中文） |
| ② 表单草稿占位 zh-CN | `FloatingAccountPanel.vue` `preferenceDraft` 初始值、`PreferencesTab.vue` 两个 props default 均写死 `'zh-CN'` | 占位值未跟随新默认语言策略 | 面板/偏好 Tab 在偏好数据尚未就绪或缺失时的兜底展示 |

### 受影响模块

- 偏好 store 归一链路（`useUserPreferencesStore.ts` `normalizePreferences`）
- 账号面板偏好表单（`FloatingAccountPanel.vue` / `PreferencesTab.vue`）草稿与 props 默认值、本地 normalize 兜底

### 选定方案

统一语义：**语言为空/缺失 = 「未设置偏好」→ 跟随浏览器默认语言（`detectSystemLanguage()`：中文环境 zh-CN，其它 en-US）；显式非空值仍按支持集归一（仅 zh-CN / en-US）**。与 V3.5.22 的默认语言策略完全一致，消除「空 → 中文」这一历史遗留的特例。

不改动 `normalizeLocaleLanguage` 导出契约（`setLocaleLanguage` / 语言切换器等显式输入路径语义不变），只在偏好映射层补空值兜底。

## 二、修改内容

1. `frontend/src/domains/common/user/stores/useUserPreferencesStore.ts`
   - `normalizePreferences` 的 language 字段改用新增 `normalizePreferenceLanguage()`：空值/缺失 → `detectSystemLanguage()`；非空 → `normalizeLanguage`（显式 zh-CN/en-US 之外归 zh-CN，保持原契约）。
2. `frontend/src/domains/common/user/components/FloatingAccountPanel.vue`
   - `preferenceDraft` 初始值 `language: 'zh-CN'` → `detectSystemLanguage()`；
   - 本地 `normalizePreferences` 空语言兜底 → `detectSystemLanguage()`（覆盖「远端 saved 空语言」路径）。
3. `frontend/src/domains/common/user/components/tabs/PreferencesTab.vue`
   - 两个 props default 的 `language: 'zh-CN'` → `detectSystemLanguage()`；
   - 本地 `normalizeLanguage` 空值兜底 → `detectSystemLanguage()`。

两组件均已在 import `useLocale` 处扩展 `detectSystemLanguage`。

## 三、修改原因

用户明确要求修复 V3.5.22 遗留两项；统一「空语言 = 跟随系统」语义后，远端空语言、草稿占位、面板本地归一三处行为与全局首屏策略一致，不再出现「浏览器英文用户被远端空值或表单兜底拉回中文」的缝隙。

## 四、影响范围

- 登录用户偏好合并（远端空语言不再冲回 zh-CN）
- 账号中心偏好表单的草稿/兜底展示语言
- 无其它模块；首屏初始语言（V3.5.22 已实现）行为不变

## 八、遗留与风险

- 显式但不受支持的语言值（如远端历史脏数据 `'fr'`）仍归 `zh-CN`（`normalizeLocaleLanguage` 原契约），未纳入本次「空值」兜底范围；如未来需要，可在 `normalizePreferenceLanguage` 中把非支持集一并映射到 `detectSystemLanguage()`。
